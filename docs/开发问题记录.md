## AI-ASSIST-03：手动辅助调用超时边界与脱敏诊断

- 发生时间：2026-10-20 16:52–17:04（Asia/Shanghai）。
- 现象：独立 `MANUAL_ASSISTANCE` 曾连续两次约 45 秒后以 `OpenAIIoException` 失败；Java/WireMock
  结果仍为 `PASS / RECOVERED`。规划与审核也使用同一 `AiGateway.chat()`，共享 JSON response format、
  `maxRetries(0)` 和对话模型；差异仅在角色与载荷，不能把故障臆断为提示词、供应商或 JSON 问题。
- 可控复现：WireMock `/v1/chat/completions` 延迟 2500ms，模型超时配置 1s，单次请求后失败。
  实际脱敏异常类别链观测到 `OpenAIIoException -> InterruptedIOException -> SocketException`，
  以及 `OpenAIIoException -> InterruptedIOException -> SocketTimeoutException` 两种；
  都是在 HTTP 请求受限超时后失败，不是固定一种底层终点，也不是 `HttpTimeoutException`。
  请求计数为 1，未发生自动重试。
- 处理：`AiGateway` 仅记录有限长度的异常类名链、阶段、耗时和超时配置；不传播异常正文、
  请求体、密钥、Authorization 或完整 stack trace。对 `MANUAL_ASSISTANCE` 使用独立的 12 秒
  辅助等待上限，并按超时配置分别缓存 chat client，避免先创建的规划/审核 client 覆盖手动边界；
  全局规划/审核超时、`maxRetries(0)`、Java 结果与 AI 状态分离均保留。
- TDD/回归：新增传输超时、根因类别、单请求、脱敏测试；`mvnw.ps1 -B '-Dstyle.color=never' verify`
  通过，`56 tests`，Failures=0，Errors=0，Skipped=0。
- 受控真实验收：任务 `77071db8-845c-443e-aa17-7586497fbf26`，仅 1 次人工辅助调用；
  Java `PASS / RECOVERED`，2 次本地 HTTP 请求，AI `COMPLETED`，模型调用 `13518ms`，
  端到端约 `15655ms`。证据：`runtime/evidence/manual-ai-assistance-fix-report.json`。
- 边界：本地复现已查明 SDK 传输超时的异常类别链；真实供应商持续稳定性、该链在其他网络/模型条件下
  的一致性仍 `NOT_VERIFIED`。本修复不增加重试，不把一次真实成功宣称为生产可靠性。
